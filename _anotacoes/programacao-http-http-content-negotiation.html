Em uma determinada URI podemos ter diversos tipos de recursos podendo ser requisitados, de uma olhada na imagem a abaixo:

O cliente está passando nos headers da requisição um header chamado Accept, esse header diz que ele aceita um recurso chamado text/html, o webserver então olha nos recursos dele e ve que tem uma pagina HTML ali, envia a resposta então com o header Content-Type text/html dizendo que no body tem um HTML, mas embaixo o cliente pede um application/json, que o server não tem então ele responde com 406 Not Acceptable.

As negociações sempre acontecem no header das requisições e os mais famosos são:

  • Accept: Esse header geralmente vem na requisição feita pelo cliente, ele envia o tipo de dado que espera receber no body da resposta do webserver. Ele utiliza categorias como text,audio application, para dizer o tipo de dado que espera receber no caso acima é text/html, ele espera receber um arquivo de texto html, mas poderiamos ter por exemplo application/json, dizendo que o json é uma aplicação do javascript.

  • Accept-Charset: Diz qual o charset(UTF-8) que o cliente espera receber a resposta.

  • Accept-Datetime: Diz que quer a versão do recurso num horario anterior ao qual a requisição está sendo feita, não vc não pode pedir coisas do futuro.

  • Accept-Language: A lingua que o cliente espera receber o conteudo do body da resposta.

Quality Factor Weighting

Podemos também passar valores dentro do header para escolher um tipo ao em vez do outro por exemplo:

Accept: text/html , application/json;eq=0.9 , application/xml;eq=0.8 , *;eq=0.7

No caso acima ele vai mostrar o text/html para você caso ele tenha, senão o application/json vai ser o segundo escolhido e o application/xml o terceiro, se ele não tiver nada a * diz para mostrar qualquer coisa.

Temos dois tipos de negociação, a negociação feita pelo cliente e a negociação feita pelo servidor:

Negociação feita pelo servidor:

  1. Cliente faz a requisição, e o servidor decide que tipo vai enviar para ele.

Negociação feita pelo cliente:

  1. O cliente faz uma requisição falando que quer um recurso em certa URI.
  2. O servidor responde com 300 Multiple Choises, falando tenho esses aqui qual vc quer?
  3. O cliente escolhe então XML no caso e faz a chamada para a URI especifica do recurso XML( HTTP REDIRECTION)
  4. 200 OK com o body XML.
