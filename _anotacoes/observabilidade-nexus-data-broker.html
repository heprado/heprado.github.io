Flow Analysis - Analisar somente os headers do pacote, para saber quem está se comunicando com o que.

Packet Analysis - O pacote inteiro, incluindo o payload, usado bastante para parte de segurança.

Tipos de Packet Monitoring

OOB - Cria uma copia do pacote e joga para uma rede separada, para assim o pacote ser analisado. (SPAN/RSPAN/TAP)

Inline - A rede de packet broker fica no meio da produção, enviando os pacotes para as ferramentas de monitoramento, essas que podem escolher dropar o tráfego caso ele seja malicioso, geralmente gera latencia pois vc está adicionando mais um hop na sua rede. Muito usado para mandar tráfego para um appliance de IPS, para ela tomar uma decisão de encaminhamento como fazer blackhole desse trafégo.

Nexus Data Broker Architecture

NDB Switching Layer - Feita de Switches Nexus com todas as funcionalidades de switching e routing desabilitadas, são os switches que vão receber a copia ou se estiverem in-line o tráfego real e enviar para as ferramentas de monitoramento, IPS/IDS/Wireshark/Gigamon etc… OBS: Você ainda precisa de spanning-tree rodando na sua rede mesmo que ele não faça switching, acredito que de alguma forma os switches broker devem fazer alguma comunicação broadcast então, ninguem gosta de broadcast storm….

NDB Controller Layer - É a controladora onde criamos todas as regras de brokering, exemplo seria pacotes UDP para a porta 1574 vão para certa ferramenta de monitoramento, pacotes TCP para porta 443 vão para um IPS, a contorladora configura os switches broker através de NX-API ou Open-Flow.

Essa controladora pode estar em uma VM ou dentro de um switch Nexus com GUEST SHELL, a principal diferença é que se você subir dentro de um switch com guest shell você só vai poder gerenciar aquele switch broker então esse modelo não é recomendado para ambientes maiores, já na VM podemos gerenciar diversos switches broker.

NDB Automation Customer Application - A controladora ainda expoe uma REST API para você criar ferramentas de automação, parecida com o ACI. Você pode configurar a controladora inteira via programabilidade.

Packet Modification at Ingress

Dot1q Tagging - Você pode escolher taggear o tráfego que estiver chegando em certa porta para uma certa VLAN, para casos de identificação do tráfego.

VLAN and MPLS Label Stripping - Possui a capacidade de remover os headers de 802.1Q e de MPLS, assim vc fica somente com os headers do frame sem ser encapsulado em algum outro protocolo.

PTP Time-Stamping - Consegue fazer time stamping dos pacotes/frames , funciona somente com o PTP, então nada de NTP por aqui…

Truncation - Você pode escolher remover os headers e mandar somente o payload para a ferramente de monitoramento e fazer também o inverso disso, remover o payload e mandar somente os headers. Isso entra na parte de Flow Analysis ou Packet Monitoring, se você for fazer flow analysis pode fazer truncation do payload e mandar somente os headers, e o inverso para packet monitoring.

IMPORTANTE - O NDB só consegue cortar um pacote a partir de um offset, vc não consegue remover somente uma parte de um header por exemplo, ou ele remove tudo a partir de um offset ou não remove nada.
