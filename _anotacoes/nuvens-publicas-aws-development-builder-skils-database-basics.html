Database Types

Relational Databases

Os dados são estruturados ou seja possui um esquema de como os dados das tabelas devem ser inseridos.

Document Databases (noSQL)

Guarda documentos geralmente JSON,BSON,XML, podemos usar a query engine do banco para consultar esses documentos e retornar somente os que possuem certo valor.

Você pode definir um schema para os documentos mas não é necessario igual a banco de dados Relacionais.

In Memory Databases

São bancos de dados que não persistem nenhuma informação, mas por estarem direto na memoria RAM são muito mais performáticos, pois não precisam passar pelo I/O para gravar os dados em um HD ou SSD por exemplo.

Key-Value Databases

Podem possuir um esquema mas geralmente não possuem, são utilizadas para retornarem coleções de CHAVES:IDENTIFICADOR -> VALORES, costuma ser mais performatico que um bancos de dados relacionais

Exemplos: REDIS

Graph Databases

Utiliza grafos para representar os relacionamentos entre as entidades salvas no banco.

Formas de usar

Você pode utilizar os serviços de PaaS dos bancos de dados que são os citados a cima, mas se quiser você tem a total liberdade de subir uma instancia EC2(IaaS) e configurar o banco de dados que quiser dentro dela.

Partitioning

Podemos particionar uma tabela em um banco de dados, vamos dizer que temos uma tabela chamada VENDAS com as seguintes colunas:

  • PK id_produto
  • INT valor_pago
  • DATA data_venda

Podemos particionar essa tabela utilizando o data_venda, separando em varias tabelas uma pra cada mês ou até por ano se tivermos vendas de mais de um ano.

Sharding

Sharding é pegarmos uma tabela e separar os dados dela em mais de um banco de dados, isso melhora bastante o throughput do banco de dados pois as consultas são dividas em duas instancias botamos menos pressão em no armazenamento do servidor que tá rodando o banco de dados.
