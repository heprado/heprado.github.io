Fazer software modular trás diversas coisas boas para um projeto mas temos sempre que pensar em algo muito importante:

UM MUDANÇA EM MODULO NÃO PODE QUEBRAR O SISTEMA INTEIRO, OS MODULOS PRECISAM SER INDEPENDENTES, E TER INTERFACES MUITO BEM DEFINIDAS PARA QUE AS MUDANÇAS NÃO QUEBREM TUDO.

Os principais designs utilizados são os seguintes:

  • Acyclic dependencies principle
  • Stable dependencies principle
  • Single responsibility principle

Veja a imagem abaixo, temos dois módulos, o modulo a consome e prove metodos para o modulo B, percebe que algum input errado no modulo C pode causar um problema no sistema inteiro? Isso abaixo deve ser evitado ao maximo.

O Modulo init testa o APP para ver se está tudo ok e só assim inicia, para quebrar esse ciclo só precisamos por mais um modulo :

Loose Coupling

Um modulo que depende de diversos metodos de outros modulos não é algo muito bom, pois fica INCRIVELMENTE dificil de fazer um troubleshooting, então utilizamos o Loose Coupling que é fazer um modulo que depende o minimo possivel de outros modulos para reduzir a complexicidade.

Cohesion

Para termos um bom codigo cada função precisa fazer uma COISA SÓ, não podemos ter uma função que por exemplo cria um log e envia esse log para tal email, precisamos criar uma função para criar os logs e outra para enviar os emails.
