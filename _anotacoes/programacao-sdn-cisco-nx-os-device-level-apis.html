MDP (Model Driven Programmability)

O NX-OS usa exatamente a mesma estrutura que o ACI, a MIT do ACI é o MDP do NX-OS.

Um exemplo seria para configurar uma instancia de BGP:

A URI seria “/api/mo/sys/bgp.json”, embaixo dessa uri tem o objeto parente chamado bgpInst, então o payload seria:

{
	"bgpInst":{
	"attributes":{
	"asn":"100",
	"rn":"inst"
	},
	"children":[

	"attributes":{
	"name":"vrf1",
	"rn":"dom-vrf1"
	},
	"children":[
		{
		"bgpPeer":{
		"attributes":{
		"addr":"10.1.1.1",
		"inheritContPeerCtrl":"",
		"rn":"peer-\[10.1.1.1\]"
		}
}

Formas de automatização NX-OS

NX-API CLI

Esse metodo é bem maneiro pois conseguimos mandar comandos de CLI via HTTPs, encapsulamos ele dentro do body da requisição e a NX-API vai responder o comando como se tivesse sido jogado dentro da CLI.

Podemos ver ali na chave “input” da requisição, temos o comando “show clock” sendo enviado, no body da resposta da requisição temos a chave “simple_time” mostrando o horario do dispositivo.

NX-API REST

É uma API REST exposta pelo NX-OS, ela não segue o padrão RESTCONF porque quando ela foi feita o draft do IETF não estava pronto ainda, então essa é a principal diferença entre as duas.

O recomendável é utilizar a RESTCONF, assim seu script terá maior compatibilidade com varias ferramentas, inclusive de concorrentes da Cisco.

YANG Clients

RESTCONF,NETCONF e gRPC são utilizados como transporte para requisições baseadas no modelo YANG.

NX-OS SDK

Plugin utilizado para fazer automação, funciona tanto para C++ quanto Go e Python.

Pode ser rodado tanto dentro quanto fora da caixa(RPC)

Onbox Python

O NXOS já vem com Python pre-instalado, junto com um modulo chamado cisco, podemos utilizar ele para fazer comando de CLI:

Funções principais :

  • cisco.cli(show hostname) , vai rodar o comando na CLI e te voltar o output em string pura.

  • cisco.clip(show hostname), vai rodar o comando na CLI e printar na tela pra você o resultado.

  • cisco.clid(show hostname), vai rodar o comando e te voltar uma string em formato de dicionario, só precisamos fazer um json.loads no resultado para transformamos em dicionario.

EEM

Com o EEM conseguimos fazer com que o equipamento execute comandos caso algo aconteça, no caso acima ele faz todas as “actions” caso o evento da OID de HIGH CPU aconteça, inclusive um dos comandos eu vão ser executados é um script em python, por exemplo para matar alguns processos.
