SNMP

Protocolo utilizado para monitorar equipamentos de rede.

OID ( Object Identifier ) - Um numero geralmente escrito 1.3.2.5.7.3.7.3, a combinação desses numeros é uma variavel, como CPU LOAD, RAM LOAD, UPTIME etc.

MIB (Management Information Base) - MIB compacta todos os OIDs que existem em um equipamento de rede, o fabricante fornece a MIB para o cliente.

SNMP Get - Requisição pedindo para o agente uma informação contida em uma OID.
SNMP Set - Requisição configurando o equipamento.
SNMP Trap - Quando um agente envia informações para um NMS sem ele pedir, podemos setar pra se caso uma interface caia ele envie a trap avisando o NMS.

Existem 3 versões dele, SNMPv1 SNMPv2c e SNMPv3.

SNMPV1 - Utiliza comunidades RO/RW como uma PSK, e só suportava contadores de até 32bits.

SNMPv2c - Utiliza comunidades RO/RW como uma PSK, e suporta contadores de até 64bits.

SNMPv3 - Utiliza comunidades , senhas e grupos de usuarios, suporta 64bits também.

Configurando SNMPv2c -

Snmp-server community “nome” ro

FIM.

Configurando SNMPv3 -

Snmp-server view “NOME” “OID” ( Esse comando é utilizado para criar uma View da MIB.

Snmp-server group “NOME” priv read “Nome da VIEW criada”

Snmp-server user “NOME” “GRUPO” v3 auth sha “SENHA” priv des56 “outra-senha”

IP SLA

Protocolo usado para testar se um service provider realmente está entregando a velocidade que prometeu no contrato.

Podemos utilizar um ping, um pacote SIP, uma requisição HTTP/HTTPS, qualquer coisa para medir a integridade do link

Podemos configurar ele entre um roteador e um servidor/ computador, nesse caso não estaríamos monitorando somente a rede do service provider, mas a nossa também.

Ou podemos configurar somente entre 2 roteadores, deles sendo o SLA Responder, esse SLA responder responde com os dados gerados de tempos em tempos.

Para configurarmos:

Ip sla 1
Icmp-echo “ip de destino”
Exit
Ip sla 1 scheduler life forever start-time now

SPAN

Switched Port Analyzer, configurações que podemos fazer na porta de um switch para que ela recebe frames vindos de outras interfaces do switch.

Temos como configurarmos de dois jeitos, para receber somente os frames enviados ou recebidos numa porta.

Configurando para tráfego enviado para a porta pelo switch:

Monitor session “numero da sessão” source interface “numero da interface” tx
Monitor session “numero da sessão” destination interface “numero da interface que vai estar o network analyzer.

Configurando para tráfego enviado para o switch pela porta:

Monitor session “numero da sessão” source interface “numero da interface” rx
Monitor session “numero da sessão” destination interface “numero da interface que vai estar o network analyzer.

Configurando para ambos os tráfegos:

Monitor session “numero da sessão” source interface “numero da interface” both
Monitor session “numero da sessão” destination interface “numero da interface que vai estar o network analyzer.
