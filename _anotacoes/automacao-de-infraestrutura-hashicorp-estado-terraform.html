Descrição do arquivo de estado

Como sempre falamos o Terraform mantem o estado da infraestrutura, ele faz isso mantendo todas as configurações que foram aplicadas na infraestrutura em um arquivo chamado terraform.tf.state, por isso é tão importante que todas as mudanças feitas na infraestrutura sejam feitas no Terraform pois ele não consegue saber sobre o que ele não fez, ele só sabe o que ele fez por conta desse arquivo.

Formato JSON

Esse arquivo diferente de outros arquivos do Terraform não é escrito em HCL e sim em JSON, não é recomendado mexer nele manualmente.

Mapeamento de recursos e metadados

Se refere a todos os dados que ele guarda da infraestrutura e também de si próprio, um exemplo de metadados seria a versão de terraform que criou esse arquivo.

Locking

Se o seu tf.state estiver guardado em um repositório remoto em que todos tem acesso, o terraform suporta o Locking, que é nada mais do que travar o arquivo enquanto o terraform está aplicando as configurações, assim ninguém consegue dar terraform apply na mesma infraestrutura.

Localização do arquivo,

Por padrão o Terraform guarda o arquivo tf.state na mesma pasta onde o Terraform foi executado e encontrou arquivos .tf, mas podemos utilizar repositórios remotos como um bucket na AWS ou um blob no Azure ou na própria nuvem da Hashicorp.

Informações no arquivo de estado

{
	"version":4,
	"terraform_version": "1.2.3",
	"serial": 10,
	"lineage" : "",
	"outputs" : {},
	"resources" : []
}

Version

A versão do terraform.tf.state, é incrementado cada vez que executamos o terraform apply.

Terraform_version

Esse é interessante, o Terraform checa essa chave e vê se o Terraform que está executando o terraform apply ou plan está numa versão anterior a que criou esse terraform.tf.state, se for uma versão inferior ele não deixa executar.

Serial

Se executarmos o comando terraform plan –out ele gera um arquivo chamado tfplan com o plano de execução de automações na infraestrutura, esse arquivo é um JSON que possui a mesma chave serial do arquivo terraform.tf.state, se alguma modificação for feita no terraform.tf.state esse número serial será incrementando fazendo com que o tfplan esteja num serial inferior ao do estado atual da infraestrutura, com isso o Terraform consegue saber que esse plano(tfplan) não pode ser executado em conjunto com o comando terraform apply

Outputs

Em um arquivo de configuração do terraform podemos definir outputs, esses dados além de serem salvos no terraform.tf.state, são disponibilizados logo após o terraform executar as tarefas de automações definidas em seu módulo terraform, possibilitando que outros módulos terraform utilizem os outputs que você definiu para alguma tomada de decisão.

Exemplo de output

"outputs": {
	"igw_id" : {
	"value":"igw-1234567",
	"type": "string"
  },
}

Resources

Todas as configurações que foram feitas pelo terraform na infraestrura, ele salva todos os valores necessários para configuração do recurso, com isso quando precisamos atualizar algo na infraestrutura o terraform consulta os valores desse recurso para ver se precisam ser atualizados.
