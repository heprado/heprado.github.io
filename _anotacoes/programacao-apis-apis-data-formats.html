Para que um API entenda oq queremos que ela faça precisamos passar parâmetros, e para passar esses parâmetros existem três tipos de formatos:

  • XML
    eXtensible Markup Language, é usado para trocar de informações entre aplicações, geralmente dados muito estruturados, como informações de uma conta de banco e etc, Java utiliza bastante.

XML utiliza tags que nem o HTML, para demonstramos valores fazemos <chave>valor</chave>, e dentro dessas TAGS podemos ter outras tags com suas chaves, igual um JSON que utiliza “{}” ao em vez de “<>”

XML NAMESPACES

Imagine que estamos montando um XML que vai ser mandado para duas APIs , as duas entendem as tags <calçado></calçado>, só que uma espera receber um sapato e a outra espera receber um tenis, para separar isso no mesmo XML utilizamos namespaces:

<sapato:calçado xmls:sapato=“cisco.sapatos.com”>

<sapato:tipo>Bico Fino</sapato:tipo>

<sapato:cor>Marrom</sapato:cor>

</sapato:calçado>

<tenis:calçado xlms:tenis=“cisco.tenis.com”>

<tenis:tipo>Chuteira</tenis:tipo>

<tenis:cor>Laranja</tenis:cor>
</tenis:calçado>

A URI COLOCADA NO XLMS NÃO É UTILIZADA PELO PARSER PARA NADA, SÓ SERVE PARA DIZER DE QUEM É ESSE NAMESPACE POR ISSO O PESSOAL UTILIZA O SITE PARA DIZER QUE VEM DE UMA CERTA EMPRESA.

  • JSON
    JavaScript Object Notation, serve para a mesma coisa que o XML, tirando que JSON é bem melhor para ler do XML, geralmente é utilizado em aplicações mais modernas e funciona muito bem com o proprio JavaScript já que esse tipo de formatação foi feito justamente para ele, é muito facil transformar um JSON em algo no seu código JS.

Em JSON os dados são separados por “{}”, chaves e valores são separados por “:” e depois de um

Valor sempre colocamos uma virgula, menos no ultimo.

Também temos JSON Namespaces, geralmente utilizado em RESTCONF

Myapp é o namespace, isso significa que podemos utilizar as mesmas chaves só que com um namespace diferente como myapp2.

  • YAML
    Yaml ain’t markup language(recursividade TOP), é mais facil ainda de ler do que JSON, é geralmente utilizado para arquivos de configurações, um exemplo seria Ansible, fazemos um manifesto YAML e mandamos para ele, o Ansible cuida das chamadas API para gente. É bem popular com python.

Identação é muito importante em YAML, geralmente utilizamos 2 espaços para demostrar que algo é um valor de um chave.

user:
name:john
location:
city:Austin
state:TX
roles:
- admin
- user

Todos os dados de um YAML devem ter um espaço depois de sua chave, para fazermos uma lista basta colocarmos a chave e um “-” traço para adicionarmos cada um desses itens para a lista(SIMPLESMENTE MARAVILHOSO).

Também temos YAML Namespaces, geralmente utilizado em RESTCONF

Myapp é o namespace, isso significa que podemos utilizar as mesmas chaves só que com um namespace diferente como myapp2.

A API vai pegar esse parâmetros que utilizamos na chamada na API e serializar ele em algo que o código dele consiga entender e executar.
