Configuration Management vs Infrastructure Orchestration

Configuration Management - São softwares criados para inicialmente para instalação e gerenciamentos de softwares dentro do sistema operacional do servidor, elas geralmente conseguem também prover a infraestrutura mas não é o foco principal delas.

Exemplos : Ansible,Chef,Puppet

Infrastructure Orchestration - São softwares criados para provisionar a infraestrutura, por exemplo subir uma VM, criar uma rede etc.

Exemplos: Terraform, CloudFormation(AWS)

Use o que for para configuration management para configurar o software e o que for Infrastructure Orchestration para prover infra.

As duas juntas são muito poderosas como no caso abaixo:

-Terraform prove a infraestrutura e passa para o Ansible por exemplo o IP do servidor para ele fazer SSH

-Ansible configura o linux inteiro do servidor.

Declarative vs Imperative

Declarativo - Dizemos exatamente oque queremos fazer em linguagem de codigo, não utilizamos funções que abstraem oque está sendo feito.

COMO QUEREMOS FAZER.

Linguagens Declarativas: Python, Go, Javascript

Imperativo - Dizemos o que queremos fazer e a linguagem se vira para fazer através de funções que abstraem o que está sendo feito.

O QUE QUEREMOS FAZER.

Linguagens Declarativas: HCL (Terraform), YAML, JSON

Idempotent vs Consistent

Idempotent - O Terraform é Idempotent, se você pedir para ele criar algo no código, caso rodemos ele de novo ele não vai recriar esse algo novamente, isso pois ele mantem o estado.

Consistent - Caso tivermos um codigo que cria algo, se pedirmos para rodar de novo, ele vai recriar tudo do zero, sempre entregando tudo da forma que pedimos, por isso consistente.
