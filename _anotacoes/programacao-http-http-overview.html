HTTP é um protocolo stateless ele não precisa reter nenhuma informação do cliente para conseguir se comunicar com ele, existem os headers do HTTP que fazem ele se tornar stateful.

HTTP Request

É o pacote que o navegador cliente envia para o Servidor Web, ele é composto por diversos componentes:

  • Request-line, é aqui onde escolhemos onde se encontra o metodo utilizado na requisição (GET,PATCH,PUT,POST), ele é composto por METHOD+URI+Versão do HTTP

Exemplo:

GET /resources HTTP/3

  • Os Headers HTTP, você pode ou não utilizar eles.

  • Linha em branco, dizendo que acabou os headers.

  • O body da requisição, em requisições ele é opcional, geralmente é utilizado quando vamos fazer um POST.

HTTP Response

A resposta do servidor WEB para o browser cliente, componentes:

  • Status -line, temos informações como versão do protocolo, status da requisição em numero e um formato de status da requisição em string

  • Headers, que podem ou não ser utilizados que nem o HTTP Request.

  • Linha em branco indicando final dos headers

  • Body da resposta, informações que o cliente pediu, exemplo uma imagem, ou o arquivo HTML para ele montar a pagina no navegador.

HTTP URL

Uma URL não é uma URI, URI é o Identificador de um recurso, já a URL é a localidade desse recurso.

  1. Scheme, fala o protocolo que está sendo utilizado na URL, geralmente é HTTP ou HTTPS.
  2. Host, o endereço do site, que vai ser resolvido pelo DNS.
  3. Port, a porta em que o servidor WEB está esperando receber as requisições, padrão é 80(HTTP) e 443(HTTPS)
  4. Resource Path, o caminho de onde está o que vc quer acessar
  5. Query, sempre segue depois de um “?”, é para aplicar uma logica a URL, por exemplo você quer buscar só determinados arquivos.
  6. Fragment, aponta para um documento secundario, por exemplo a segunda pagina.
