Provisioners

Provisioners são recursos que você pode utilizar dentro do terraform para fazer certas funções, como por exemplo ler um arquivo dentro da propria pasta, fechar SSH com uma maquina remota e executar comandos PowerShell ou Bash e ate executar comando Powershell ou Bash localmente, temos até um que cria chaves SSL é bem legal.

Uma coisa a se lembrar é que eles não são considerados uma boa pratica, pois o terraform não consegue manter no tf.state as configurações que foram feitas utilizando eles, o terraform não foi criado para isso, então o recomendado para fazer tarefas como configurar um NGINX dentro de um servidor, criar uma chave SSL e configurar no servidor é utilizar ferramentas como Ansible, Puppet e Chef que são Configuration Managers.

Os provisioners ficam dentro de resources e podemos ter diversos deles para fazermos diversas coisas, quando precisamos que um provisioner faça algo sem que uma resource seja chamada por exemplo do provider da AWS, podemos utilizar o resource “null-resouce” “label_two”, ela é uma resource que não depende de nenhum provider e só executa os provisioners que vc colocar lá.

Abaixo alguns dos mais utilizados:

  • File

Esse provisioner é bem util e serve basicamente para copiarmos arquivos locais para um destino.

Connection - Nessa bloco o provisioner está fazendo a conexão com o servidor que vamos configurar, passamos o type da conexão (ssh), o user que vamos logar (root), a private_key que vamos utilizar para fechar a conexão e por final o host (ip ou FQDN).

Source e destination - Origem e destino do arquivo que vamos copiar.

  • Local-exec

Esse é um dos que eu mais gosto, podemos executar comandos dentro da maquina que está rodando o terraform, como criar um arquivo com touch, ou criar uma chave SSL com o ssh-keygen, é super util.

  • Remote-exec

Scripts ou script(somente 1) - ele vai ler seus scripts locais e executar na maquina remota. OBS: ele não suporta argumentos então se vc quiser passar argumentos copia o script com o provisioner file e usa o inline para executar os arquivos com argumentos.

Inline - Você escreve os scripts diretamente no arquivo de configuração.
