Infraestrutura movida a politicas (Policy Driven Infrastructure)

Imagine um engenheiro de redes que recebeu uma politica estabelecida pela empresa de que a aplicação principal deles precisaria ter 10GBps de bandwidth garantida entre todos os componentes dela, essa aplicação é composta por um servidor Web que se conecta a uma API de consulta que posteriormente se conecta a diversos bancos de dados, dependendo do tamanho da infraestrutura esse engenheiro teria muito trabalho em encontrar as interfaces corretas para aplicar o QoS(Quality of Service) que garantiriam esses 10GBps de banda entre todos os componentes.

Então a Cisco criou a Infraestrutura movida a politicas, com isso o engenheiro de redes consulta uma controladora, define como as configurações devem ser para atender a politica dessa aplicação e a controladora configura em todos os equipamentos necessários via APIs Southbound.

Infraestrutura movida a politicas também é chamado de Redes baseadas em intenções(Intent-Based Networks).

Componentes do ACI

O ACI possui os seguintes componentes:

Endpoint

Qualquer máquina ou equipamento externo ao Fabric é considerado um Endpoint no ponto de vista do Fabric ACI.

Exemplos de endpoints são:

  • Switches
  • Roteadores
  • Mainframes
  • Servidores(Físicos, virtuais, containers)
  • Storages

APIC

Geralmente é um servidor com arquitetura x86, nele gerenciamos o control plane de todos os equipamentos pertencentes ao fabric, formas de gerenciamos o control plane são as seguintes:

  • Interface gráfica, através de um navegador utilizando HTTPs.
  • Programaticamente através de REST APIs. (Northbound APIs)
  • Utilizando a linha de comando através de conexão SSH ou porta console.

As configurações que aplicamos através do APIC são propagadas para os equipamentos do fabric utilizando APIs Southbound utilizando OpFlex (Protocolo de APIs SDN da Cisco).

O ideal é sempre termos 2 APICs sobressalentes para cada APIC, então o mínimo recomendado é sempre 3 APICs.

Leaf

Leaf é um switch onde conectamos máquinas externas ao fabric ACI, exemplos de máquinas são:

  • Switches
  • Roteadores
  • Mainframes
  • Servidores(Físicos, virtuais, containers)

Dentro de um Fabric podemos ter diversos leaves(plural de leaf) e esses leaves são interconectados utilizando os spines, por conta disso todos os leaves devem ter pelo menos uma conexão com todos os spines do Fabric.

Spine

Os spines fazem a intercomunicação entre os leaves, possuem informações de roteamento de todo o Fabric para que as máquinas externas ao fabric ACI consigam se comunicar mesmo estando entre leaves diferentes.

Como os spines se conectam a todos os leaves eles costumam ser equipamentos mais poderosos, com um backplane com capacidade de receber e encaminhar frames simultaneamente em todas as suas portas.

Fabric

Um fabric ACI é definido por equipamentos de rede que são controlados por um conjunto de APICs, esses equipamentos possuem um underlay utilizando IS-IS como protocolo de roteamento para propagar as rotas de cada VTEP(VXLAN Tunnel Endpoint), esses VTEPs são utilizados como overlay para encaminhar frames camada 2 utilizando VXLAN entre os leaves utilizando os spines como intermédio.

Porque usar ACI

Os quatro grandes motivos são:

Segurança

Numa rede tradicional , quando conectamos uma máquina e colocamos ela em uma VLAN(Virtual Local Area Network), ele vai conseguir se comunicar na Camada 2 com todos as outras máquinas nessa mesma VLAN através de tráfegos Unknown Unicast, para bloquear esse tráfego dentro da VLAN é necessário que o switch suporte Private VLANs em modo Isolated, o que não são todos os switches que possuem, ou escrever uma ACL para bloquear o tráfego na Camada 3 o que ainda não é o ideal pois o tráfego o ARP(Address Resolution Protocol) ainda irá ocorrer.

O ACI usa EPGs(End Point Groups), que por padrão permite que todas as máquinas conectadas a esse EPG se comuniquem na Camada 2 caso Intra EPG Isolation seja ativado. Podemos também utilizar ESGs(Endpoint Security Groups) para micro segmentar o EPG definindo quais máquinas dentro do EPG podem se comunicar.

Topologia Simplificada

Utiliza uma topologia do tipo Topologia CLOS, como o fabric inteiro possui um underlay em camada 3 entre os spines e leaves não existe Spanning Tree bloqueando as portas tornando possível utilizar todas as portas de uplink entre os leaves e spines simultaneamente usando ECMP(Equal Cost Multi Path).

Gerenciamento

Como configuramos a rede inteira pelos APICs, fica muito mais facil gerenciar a rede do Data Center, os APICs também nos dão varias ferramentas para troubleshooting, como health scores.

Programabilidade

O APIC possui uma API Northbound, em que podemos criar scripts/programas para automatizar a configuração de politicas.
