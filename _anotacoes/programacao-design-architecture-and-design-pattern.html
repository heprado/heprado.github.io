Architectural Patterns

A arquitetura de um projeto deve ser feita pensando nos seguintes pontos:

  • Performance
  • Availability
  • Modifiability
  • Testability
  • Usability
  • Security

Tudo isso vai depender do que o seu cliente te pediu, você precisa pensar em como seu programa vai funcionar high-level para conseguir explicar para seu cliente.

Um exemplo seria caso o cliente queria um sistema super disponivel, não pode cair nunca, você vai precisar pensar muito bem em como vai ser a arquitetura desse software para o failover acontecer.

Existem diversas arquiteturas já testadas para isso e você pode se basear nelas, são as seguintes:

  • Layered or multitier architecture pattern
  • Event-driven architecture pattern
  • Microservices architecture pattern
  • Model-View-Controller (MVC) architecture pattern
  • Space-based architecture

Layered or Multitier Architecture Pattern

Nessa arquitetura cada componente da solução possui uma função muito bem definida e são dividas em layers horizontais, não existe um maximo de layers tudo depende da sua aplicação, mas o mais comum são ter as seguintes:


**

  • Presentation Layer :

É onde o cliente interage com a aplicação, essa parte do software pega os inputs do usuario e joga para a layer inferior, que processa esses inputs e devolve ou não para a camada de apresentação para mostrar o resultado para o cliente (Tipo o Front End).

  • Business Layer:

É onde está a logica do negocio, por exemplo se for uma loja de compras, seria aqui que estaria as funções de salvar um produto num carrinho, comprar, verificar CEP etc.

  • Persistence Layer:

Essa camada faz a ponte entre a logica do negocio e o banco de dados, ela consegue pegar as informações e salvar novas informações no banco de dados, utilizando uma linguagem como SQL por exemplo.

  • Database Layer:

É onde fica os bancos de dados.

Uma coisa interessante de se pensar é que por exemplo a camada de apresentação não se importa como os dados vão ser escritos no bancos de dados, quem tem que se preocupar com isso é a Persistence Layer, fazendo assim com que as funções sejam realmente bem definidas e o sistema seja bem independente em cada uma das layers.

Software Design Patterns

A arquitetura é uma visão mais high level, as patterns de Software definem como cada componente vai funcionar, como ele vai ser escrito e como serão integrados.
